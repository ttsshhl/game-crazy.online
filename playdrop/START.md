# Запуск с нуля · подробно

Инструкция для Windows. Каждый шаг заканчивается проверкой — если она не проходит, дальше идти нельзя, иначе ошибка потянется и станет непонятно, где сломалось.

Всего шагов семь. Первые два дают работающую площадку на своём компьютере, следующие три — сохранения и панель загрузки, последние два — публикацию в интернет.

---

# Шаг 1 · Подготовка

## 1.1 Node.js

Проверить, стоит ли уже. Открыть `Пуск` → набрать `cmd` → Enter, в чёрном окне ввести:

```
node -v
```

Если ответ вида `v20.11.0` — всё есть, идти дальше. Если «не является внутренней или внешней командой» — скачать LTS-версию с [nodejs.org](https://nodejs.org), установить со всеми галочками по умолчанию, **закрыть и открыть cmd заново** и проверить снова.

## 1.2 Папка проекта

Распаковать `playdrop.zip` в удобное место, например `C:\playdrop`. Внутри должно лежать так:

```
C:\playdrop\
   index.html
   game.html
   profile.html
   admin.html
   games.json
   assets\
   sdk\
   server\
   tools\
```

Если файлы лежат кучей без папок `assets` и `sdk` — распаковалось неправильно, площадка не заработает.

**Проверка.** В cmd:

```
cd C:\playdrop
dir assets
```

В списке должны быть `style.css`, `config.js`, `db.js`, `host.js`, `catalog.js`, `library.js`, `ads.js`.

# Шаг 2 · Запуск на своём компьютере

В той же папке:

```
npx serve .
```

Первый раз спросит разрешение установить пакет — согласиться (`y`). Появится строка `Local: http://localhost:3000`.

Открыть этот адрес в браузере.

**Проверка.** Тёмно-серая страница, вверху логотип PLAYDROP и поиск, ниже крупная карточка игры и сетка из четырёх карточек. Картинок нет — обложки ещё не положены, это нормально.

Окно cmd закрывать нельзя, пока работаешь с сайтом: закроется — сайт перестанет открываться. Остановить сервер — `Ctrl+C`.

**Если страница белая и без стилей** — файлы лежат не по папкам, вернуться к 1.2.

В консоли браузера (`F12` → Console) сейчас будут красные ошибки про `supabase.co` — так и должно быть, база ещё не подключена. Каталог, запуск игр, реклама-заглушка и сохранения в браузере уже работают.

# Шаг 3 · База данных

Здесь появляются серверные сохранения, рекорды, профиль и возможность заливать игры через браузер.

## 3.1 Проект

Зайти на [supabase.com](https://supabase.com), зарегистрироваться (проще всего через GitHub), нажать **New project**.

- **Name** — `playdrop`
- **Database Password** — нажать Generate и сохранить в надёжное место. Понадобится один раз на шаге 5.
- **Region** — `Central EU (Frankfurt)`
- **Plan** — Free

Создание занимает пару минут.

## 3.2 Таблицы

Слева **SQL Editor** → **New query**.

Открыть файл `C:\playdrop\server\schema.sql` в блокноте, выделить всё (`Ctrl+A`), скопировать, вставить в окно запроса и нажать **Run** (или `Ctrl+Enter`).

Внизу должно появиться `Success. No rows returned`.

**Если ошибка на строках про `storage.objects`** — политики для файлов не создались из-за прав. Не страшно: их можно сделать кликами, см. 3.5.

**Проверка.** Слева **Table Editor** — в списке таблиц должны быть `profiles`, `game_saves`, `game_stats`, `scores`, `play_activity`, `player_streak`, `games`, `admins`, `purchases`.

## 3.3 Анонимный вход

Слева **Authentication** → **Sign In / Providers** → найти **Anonymous sign-ins** → включить переключатель → **Save**.

Без этого прогресс не будет попадать на сервер.

## 3.4 Ключи в конфиг

Слева внизу **Project Settings** (шестерёнка) → **API**. Скопировать два значения:

- **Project URL** — вида `https://abcdefghijkl.supabase.co`
- **anon public** — длинная строка, начинается на `eyJ`

Открыть `C:\playdrop\assets\config.js` в блокноте и вписать:

```js
supabase: {
  url: 'https://abcdefghijkl.supabase.co',
  anonKey: 'eyJhbGciOiJIUzI1NiIsInR5cCI6...'
}
```

Кавычки не терять. Ключ `anon` публичный и должен лежать в коде — данные защищают политики из schema.sql. Ключ `service_role` в файлы проекта не попадает никогда.

## 3.5 Хранилище файлов

Слева **Storage**. Если бакеты `games` и `covers` уже есть — шаг 3.2 отработал полностью, идти дальше.

Если их нет, создать вручную: **New bucket** → имя `games` → включить **Public bucket** → Save. Так же `covers`.

Затем **Storage** → **Policies** → у каждого бакета **New policy** → **For full customization**:

- имя `admin write`, операции INSERT, UPDATE, DELETE, в поле выражения — `is_admin()`
- имя `public read`, операция SELECT, выражение — `true`

## 3.6 Адреса

**Authentication** → **URL Configuration**:

- **Site URL** — пока `http://localhost:3000`
- **Redirect URLs** — добавить `http://localhost:3000/**`

Сюда придётся вернуться после публикации сайта.

**Проверка шага 3.** Обновить `localhost:3000`, зайти в любую игру, подождать минуту. Затем в Supabase: **Authentication** → **Users** — появился пользователь с пометкой anonymous; **Table Editor** → `play_activity` — появилась строка с секундами. На главной сайта появилась полка «Продолжить».

Если пусто — открыть `F12` → вкладка Network, найти красные запросы к `supabase.co`. Ошибка 401 на `/auth/v1/signup` означает невключённый анонимный вход (3.3).

# Шаг 4 · Права администратора

Чтобы заливать игры через браузер, нужен именной аккаунт с правами.

## 4.1 Аккаунт

**Authentication** → **Users** → **Add user** → **Create new user**:

- почта и пароль — свои, пароль запомнить
- галочку **Auto Confirm User** обязательно включить, иначе вход не пройдёт

## 4.2 Права

**SQL Editor** → New query, подставив свою почту:

```sql
insert into admins (user_id)
select id from auth.users where email = 'ваша@почта.ru'
on conflict (user_id) do nothing;
```

Run. Ответ `Success. No rows returned` **не означает, что всё получилось**: такую же надпись Postgres выдаёт, если пользователь с этой почтой не найден и вставлять было нечего. Настоящая проверка — отдельным запросом:

```sql
select u.email,
       u.email_confirmed_at is not null as confirmed,
       a.user_id is not null            as is_admin
  from auth.users u
  left join admins a on a.user_id = u.id
 where u.email = 'ваша@почта.ru';
```

Должна вернуться одна строка, где `confirmed` и `is_admin` равны `true`.

Если `confirmed` оказался `false` — галочка Auto Confirm при создании не сработала, и вход выдаст «Email not confirmed». Лечится запросом:

```sql
update auth.users
   set email_confirmed_at = now()
 where email = 'ваша@почта.ru'
   and email_confirmed_at is null;
```

Либо кликами: Authentication → Users → три точки справа от пользователя → Confirm email.

Если строк ноль — пользователя нет в базе, вернуться к 4.1.

**Проверка.** Открыть `http://localhost:3000/admin.html`, войти по этой почте и паролю. Вместо формы входа должна открыться панель с полями «Файл игры», «Название» и списком игр.

Если пишет «Этот аккаунт не в списке администраторов» — запрос из 4.2 не нашёл пользователя, проверить почту на опечатки.

# Шаг 5 · Перевод на английский (можно пропустить)

Без этого шага панель работает, только английские поля придётся заполнять руками. Кнопка «Перевести» будет выдавать ошибку — это не поломка.

## 5.1 Привязка проекта

В cmd, в папке проекта:

```
npx supabase login
```

Откроется браузер, подтвердить вход. Затем нужен идентификатор проекта: он есть в адресе дашборда `supabase.com/dashboard/project/ЭТО_ОН` или в Project Settings → General → Reference ID.

```
npx supabase link --project-ref ЭТО_ОН
```

Спросит пароль базы — тот, что сохранён на шаге 3.1.

## 5.2 Функция

```
npx supabase functions deploy translate
```

## 5.3 Ключ

Вариант с лучшим качеством — ключ Claude (подойдёт тот же, что работает в Looksy):

```
npx supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
```

Или Яндекс Переводчик:

```
npx supabase secrets set YANDEX_TRANSLATE_KEY=... YANDEX_FOLDER_ID=...
```

Без ключей функция использует бесплатный MyMemory — качество машинное, но для трёх коротких строк годится.

**Проверка.** В панели заполнить «Название» и нажать **Перевести** — английские поля заполнятся сами.

# Шаг 6 · Первая игра

## 6.1 Через панель — для одностраничных игр

Подходит, если вся игра в одном `.html` файле (весь код внутри, библиотеки с CDN).

Открыть `/admin.html`, заполнить:

- **Файл игры** — выбрать `.html`
- **Иконка** — картинка 4:3, примерно 640×480
- **Название**, **Описание**, **Жанр** — по-русски
- **Адрес игры** — заполнится сам латиницей
- **Перевести** → английские поля
- **Загрузить игру**

Появится зелёная строка с адресом. Игра сразу видна в каталоге.

## 6.2 Через командную строку — для многофайловых билдов

Если игра — папка с `index.html`, бандлами, текстурами и звуками:

```
node tools\add-game.js "C:\projects\jackie\dist" --id jackie --title "Джеки: Свалка до Луны" --genre Платформер
```

Скрипт скопирует билд внутрь проекта, подменит Yandex SDK на свой и допишет строку в `games.json`. Обложку положить в `assets\covers\jackie.jpg`.

**Проверка.** Открыть игру из каталога: она запускается, серый лоадер исчезает, сохранения переживают перезагрузку страницы.

**Если чёрный экран** — `F12` → Network → искать красные 404. Обычно виноваты пути от корня: на Яндексе игра лежала в корне домена и `src="/build/game.js"` работал, здесь нужен `src="build/game.js"`.

**Если лоадер не исчезает** — игра не вызывает `LoadingAPI.ready()`. Либо добавить вызов в код игры, либо удалить блок `<div class="loader" id="loader">…</div>` из `game.html`.

# Шаг 7 · Публикация в интернет

## 7.1 Загрузка на GitHub

Если Git не стоял — поставить с [git-scm.com](https://git-scm.com), все настройки по умолчанию, затем перезапустить cmd.

Создать пустой репозиторий на github.com (без README), назвать `playdrop`. Затем в папке проекта:

```
git init
git add .
git commit -m "playdrop"
git branch -M main
git remote add origin https://github.com/ttsshhl/playdrop.git
git push -u origin main
```

## 7.2 Включить сайт

На странице репозитория: **Settings** → **Pages** → Source: **Deploy from a branch** → Branch: `main`, папка `/ (root)` → **Save**.

Через пару минут сайт будет доступен по `https://ttsshhl.github.io/playdrop/`.

## 7.3 Свой домен

У регистратора домена добавить четыре A-записи для `@`:

```
185.199.108.153
185.199.109.153
185.199.110.153
185.199.111.153
```

и CNAME для `www` → `ttsshhl.github.io`.

В **Settings** → **Pages** → **Custom domain** вписать домен, сохранить, дождаться галочки и включить **Enforce HTTPS**. Обновление записей занимает от получаса до суток.

## 7.4 Обновить адреса в Supabase

Обязательный шаг, иначе вход администратора не будет работать на живом сайте.

**Authentication** → **URL Configuration**: Site URL — адрес сайта, в Redirect URLs добавить `https://ваш-домен/**`, `http://localhost:3000/**` оставить.

**Проверка шага 7.** Открыть сайт с телефона: каталог грузится, игра запускается, `/admin.html` пускает по паролю.

# Что должно работать в итоге

- Каталог открывается, игры запускаются в рамке плеера.
- Реклама-заглушка ставит игру на паузу и возвращает управление.
- После минуты игры на главной появляется полка «Продолжить», в профиле — время, уровень и серия дней.
- `/admin.html` пускает только по паролю администратора, форма заливает игру за один клик.
- У посетителя с английским браузером названия и описания на английском.

# Частые ошибки

**Белая страница без стилей.** Файлы распакованы без структуры папок. Проверить `dir assets`.

**«npx не является командой».** Node.js не установлен или cmd не перезапущен после установки.

**Страница вообще не открывается.** Закрыто окно с `npx serve`. Запустить заново из папки проекта.

**В консоли ошибки про supabase.co, прогресс не сохраняется.** Не вписаны ключи (3.4) или не включён анонимный вход (3.3).

**При входе «Email not confirmed».** Почта не подтверждена — выполнить `update auth.users set email_confirmed_at = now()` из 4.2 или подтвердить кликами в Authentication → Users.

**Панель пишет, что аккаунт не администратор.** Запрос из 4.2 не нашёл пользователя (опечатка в почте) либо не выполнялся. Прогнать проверочный `select` оттуда же — он сразу покажет, в чём дело.

**Игра не загружается через панель, ошибка про policy.** Не создались политики хранилища — вернуться к 3.5.

**Кнопка «Перевести» ругается.** Не задеплоена функция (шаг 5). Английские поля можно заполнить руками, на работу площадки это не влияет.

**Supabase не открывается без VPN.** Такое бывает у части провайдеров. Проверить с мобильного интернета. Если недоступен именно рабочий адрес проекта, а не дашборд, площадку придётся переводить на свой бэкенд — Node на Railway у тебя уже освоен, схема таблиц переносится в обычный Postgres почти без правок.

**После публикации не работает вход админа.** Не обновлены адреса в Supabase (7.4).
