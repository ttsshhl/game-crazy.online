# Публикация на своём домене

Площадка статическая, поэтому подойдёт любой хостинг. Ниже два варианта: GitHub Pages (бесплатно, проще) и Railway (если билды тяжёлые). Дальше — настройка домена и обязательные правки в Supabase.

Заложи на это вечер: сама публикация занимает минут двадцать, но DNS-записи расходятся по интернету от получаса до суток.

---

## Вариант А · GitHub Pages

Бесплатно, с автоматическим HTTPS. Ограничения: репозиторий до 1 ГБ, отдельный файл до 100 МБ. Для игр, залитых через панель, это неважно — они лежат в Supabase Storage, а не в репозитории.

### 1. Убрать лишнее из репозитория

В папке проекта создать файл `.gitignore`:

```
node_modules/
.DS_Store
Thumbs.db
```

Ключ `anon` из `config.js` коммитить можно и нужно — он публичный по назначению, доступ к данным ограничивают политики RLS. А вот `service_role` в проекте не должен появляться никогда.

### 2. Залить

Если Git не установлен — взять с [git-scm.com](https://git-scm.com), настройки по умолчанию, затем перезапустить cmd.

Создать на github.com пустой репозиторий `playdrop` (без README и лицензии). Затем:

```
cd C:\playdrop
git init
git add .
git commit -m "playdrop"
git branch -M main
git remote add origin https://github.com/ttsshhl/playdrop.git
git push -u origin main
```

### 3. Включить сайт

В репозитории: **Settings** → **Pages** → Source: **Deploy from a branch** → Branch `main`, папка `/ (root)` → **Save**.

Через две-три минуты сайт откроется по адресу `https://ttsshhl.github.io/playdrop/`. Проверить, что каталог грузится и игра запускается.

### 4. Обновления в дальнейшем

```
git add .
git commit -m "что изменил"
git push
```

Сайт обновится сам за минуту-две.

## Вариант Б · Railway

Имеет смысл, если игры лежат в репозитории и весят много.

В папке проекта создать `package.json`:

```json
{
  "name": "playdrop",
  "private": true,
  "scripts": { "start": "npx serve . -l $PORT" }
}
```

Затем:

```
npm i -g @railway/cli
railway login
railway init
railway up
```

Домен подключается в настройках сервиса: **Settings** → **Networking** → **Custom Domain**, Railway покажет CNAME-запись, которую нужно добавить у регистратора.

## Домен

### Если домен на reg.ru или похожем регистраторе

Зайти в управление DNS домена и добавить записи.

Для GitHub Pages — четыре A-записи на корень:

| Тип | Имя | Значение |
|---|---|---|
| A | @ | 185.199.108.153 |
| A | @ | 185.199.109.153 |
| A | @ | 185.199.110.153 |
| A | @ | 185.199.111.153 |
| CNAME | www | ttsshhl.github.io. |

Старые A-записи на прежний адрес удалить, иначе домен будет открывать то одно, то другое.

Затем в репозитории **Settings** → **Pages** → **Custom domain** → вписать домен → **Save**. GitHub создаст в репозитории файл `CNAME` — это нормально, не удалять. Дождаться зелёной галочки проверки DNS и включить **Enforce HTTPS** (галочка станет доступна не сразу, сертификат выпускается до часа).

### Если домен на Cloudflare

Записи те же, но проксирование (оранжевое облако) для начала лучше выключить — с ним GitHub дольше выдаёт сертификат. Режим SSL поставить **Full**, иначе будет бесконечный редирект.

### Проверка

```
nslookup ваш-домен.ru
```

Должны отвечать адреса GitHub. Если отвечает старый хостинг — записи ещё не разошлись, подождать.

## Обязательно после публикации

### 1. Адреса в Supabase

**Authentication** → **URL Configuration**:

- **Site URL** — `https://ваш-домен.ru`
- **Redirect URLs** — добавить `https://ваш-домен.ru/**`, строку с localhost оставить для локальной разработки

Без этого вход в панель на живом сайте не сработает.

### 2. Проверить загрузку игр с домена

Открыть `https://ваш-домен.ru/admin.html`, войти, залить пробную игру. Если панель ругается на CORS, добавить домен в **Project Settings** → **API** → **CORS** (в новых проектах разрешены все источники, и трогать ничего не нужно).

### 3. Пройти по чек-листу

- каталог открывается с телефона и компьютера;
- игра запускается, реклама-заглушка ставит её на паузу;
- после минуты игры в профиле растёт время, появляется полка «Продолжить»;
- аватар и имя меняются и сохраняются после перезагрузки;
- `/admin.html` пускает только по паролю администратора;
- в адресной строке замок, без предупреждений о сертификате.

## Мелочи, которые стоит сделать сразу

**Иконка сайта.** Положить `favicon.ico` в корень — иначе в логах будут вечные 404, а во вкладке пустой квадрат.

**Закрыть панель от индексации.** В `admin.html` уже стоит `noindex`. Дополнительно можно создать в корне `robots.txt`:

```
User-agent: *
Disallow: /admin.html
Allow: /
```

**Описание для соцсетей.** В `<head>` файла `index.html` добавить, чтобы ссылка на площадку разворачивалась картинкой:

```html
<meta property="og:title" content="PLAYDROP — играй в браузере">
<meta property="og:description" content="Браузерные игры без установки">
<meta property="og:image" content="https://ваш-домен.ru/assets/og.jpg">
<meta property="og:type" content="website">
```

**Счётчик.** Яндекс.Метрика ставится обычным кодом в `<head>`. Смотреть в ней стоит не посещаемость, а долю тех, кто вернулся на следующий день — именно на это работают полка «Продолжить» и серия дней.

## Если что-то пошло не так

**Сайт открывается, но без стилей.** Указана не та папка в настройках Pages, либо структура каталогов не сохранилась при коммите.

**404 при заходе на домен.** DNS-записи ещё не разошлись, либо в Pages не сохранён Custom domain.

**«Not Secure» и предупреждение браузера.** Сертификат ещё не выпустился. Подождать час, затем включить Enforce HTTPS.

**Игры не грузятся, в консоли ошибки CORS.** Домен площадки не совпадает с тем, что записан в Supabase, либо бакеты `games` и `covers` перестали быть публичными.

**Вход в панель не работает только на домене.** Не обновлён Site URL (пункт 1 выше).
