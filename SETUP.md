# Запуск PLAYDROP · пошагово

Порядок такой: сначала площадка работает вообще без бэкенда, потом добавляется Supabase, потом реклама, и только в самом конце — именованный вход. Каждый этап самостоятельный, можно остановиться на любом.

---

## Этап 0 · Локальная проверка (5 минут, ничего не нужно)

```bash
cd playdrop
npx serve .
```

Открыть `http://localhost:3000`. Через `file://` не заработает: браузер не грузит ES-модули с файловой системы.

Сейчас каталог показывает игры, плеер открывает iframe, реклама крутит заглушку с таймером, прогресс пишется в localStorage. Supabase ещё не подключён — в консоли будут ошибки сети от него, это нормально и ни на что не влияет.

### Как залить свою игру

**Скриптом** — берёт папку с билдом и делает всё сам:

```bash
node tools/add-game.js "C:\\projects\\jackie\\dist" --id jackie --title "Джеки: Свалка до Луны" --genre Платформер --tag Хит
```

Он скопирует билд в `games/jackie/`, подменит подключение Yandex SDK на своё, допишет строку в `games.json` и предупредит о путях, которые сломаются. Останется положить обложку `assets/covers/jackie.jpg` (640×480, 4:3).

**Вручную**, если хочется контроля:

1. Скопировать билд в `games/<id>/`, внутри обязателен `index.html`.
2. В этом `index.html` заменить строку подключения:

```html
<!-- было -->
<script src="https://yandex.ru/games/sdk/v2"></script>
<!-- стало -->
<script src="../../sdk/playdrop-sdk.js"></script>
```

3. Добавить запись в `games.json`:

```json
{
  "id": "jackie",
  "title": "Джеки: Свалка до Луны",
  "developer": "ttsshhl",
  "genre": "Платформер",
  "tag": "Хит",
  "cover": "./assets/covers/jackie.jpg",
  "url": "./games/jackie/index.html",
  "description": "Только вверх. Одна ошибка — и ты снова внизу.",
  "featured": true
}
```

Весь остальной код игры не трогается: `YaGames.init()`, `ysdk.adv.showRewardedVideo`, `player.setData`, лидерборды, `deviceInfo`, `getStorage` — SDK перехватывает вызовы и отдаёт их порталу.

### На что смотреть при переносе

**Пути от корня сайта.** На Яндексе игра лежала в корне своего домена, и `src="/build/game.js"` работал. Здесь она в подпапке — такие пути ведут в никуда. Нужны относительные: `src="build/game.js"`. Скрипт выводит список найденных, но проверяет только `index.html` — пути внутри JS-бандлов и загрузчиков ассетов надо смотреть глазами.

**Звук.** Браузер не даст запустить аудио до первого клика. На Яндексе это маскировалось их прелоадером; здесь, если игра стартует со звуком сразу, он молча не включится. Лечится запуском `AudioContext.resume()` по первому касанию.

**Размер.** Три ГБ ассетов через iframe грузятся так же, как везде. GitHub Pages держит репозиторий до 1 ГБ и файл до 100 МБ — для тяжёлых билдов лучше Railway.

**Лоадер портала.** Он висит поверх игры, пока та не вызовет `LoadingAPI.ready()`. Если у игры свой прелоадер и вызова нет — лоадер не уйдёт. Либо добавить вызов, либо убрать блок `#loader` из `game.html`.

### Проверка

Открыть `http://localhost:3000/game.html?id=<id>` и пройти по списку: игра запускается, лоадер исчез, реклама ставит игру на паузу и возвращает управление, сохранение переживает перезагрузку страницы, в консоли нет 404 по ассетам.

## Этап 1 · Supabase

### 1.1 Проект

[supabase.com](https://supabase.com) → New project. Регион — Frankfurt (ближайший к РФ из доступных). Пароль базы сохранить, он понадобится только для прямого доступа к Postgres.

### 1.2 Таблицы

SQL Editor → New query → вставить целиком `server/schema.sql` → Run.

Файл идемпотентный: его можно выполнять повторно после обновлений, данные не теряются.

### 1.3 Анонимный вход

Authentication → Sign In / Providers → **Anonymous sign-ins** → включить.

Это ключевой пункт. Без него площадка не сможет писать прогресс на сервер, пока игрок не залогинится.

### 1.4 Ключи

Project Settings → API. Скопировать **Project URL** и **anon public** ключ в `assets/config.js`:

```js
supabase: {
  url: 'https://abcdefgh.supabase.co',
  anonKey: 'eyJhbGciOi...'
}
```

`anon` ключ публичный, он и должен лежать в клиентском коде — доступ к данным ограничивают политики RLS из `schema.sql`. Ключ `service_role` в клиент не попадает никогда.

### 1.5 Адреса

Authentication → URL Configuration → Site URL: `https://playdrop.ru`. В Redirect URLs добавить и `http://localhost:3000/**` для локальной разработки.

### Проверка

Перезагрузить локальную страницу, зайти в игру, поиграть минуту. В Table Editor должны появиться строки в `play_activity`, а в Authentication → Users — анонимный пользователь. На главной появится полка «Продолжить», в профиле — время и серия дней.

## Этап 1.5 · Панель загрузки игр

Позволяет заливать игры прямо с компьютера через браузер, без git и без правки `games.json`. Работает только для аккаунтов из таблицы `admins` — у всех остальных страница показывает форму входа и дальше не пускает.

### Сделать себя администратором

Authentication → Users → **Add user** → свои почта и пароль (галочку «Auto Confirm User» включить). Затем в SQL Editor:

```sql
insert into admins (user_id)
select id from auth.users where email = 'ваша@почта.ru';
```

Проверить: `select is_admin();` под своим аккаунтом вернёт `true`.

### Перевод на английский

```bash
supabase functions deploy translate
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
```

Ключ можно взять тот же, что работает в Looksy. Альтернативы: `YANDEX_TRANSLATE_KEY` + `YANDEX_FOLDER_ID` для Яндекс Переводчика, либо вообще без ключей — тогда используется бесплатный MyMemory, качество машинное, но для трёх коротких строк сойдёт.

Функция проверяет `is_admin()` перед работой, так что чужие запросы не потратят ни токена.

### Как заливать

Открыть `/admin.html` (ссылка появляется в профиле, если аккаунт админский), войти по почте и паролю, заполнить форму:

- **файл игры** — один `.html`, до 50 МБ;
- **иконка** — картинка 4:3;
- **название, описание, жанр** — по-русски;
- кнопка **Перевести** заполняет английские поля, их можно поправить руками.

При загрузке в HTML игры автоматически подставляется `<script>` с SDK площадки: если внутри был Yandex SDK, он заменяется, если не было ничего — тег добавляется в `<head>`. Файл кладётся в Storage, строка — в таблицу `games`, каталог подхватывает её сразу.

Ниже формы — список загруженного, где игру можно скрыть с витрины или удалить вместе с файлами.

### Что важно понимать про формат

Панель рассчитана на **одностраничные игры**: весь код в одном HTML, ассеты либо внутри, либо с CDN. Твой PEW PROTOCOL и Three.js-игры, собранные в один файл, зайдут как есть.

Многофайловые билды (папка с `build/game.js`, текстурами, звуками) через эту форму не загрузить — для них остаётся `tools/add-game.js` и заливка в репозиторий. Обе схемы работают одновременно: каталог берёт игры из базы, а если база недоступна, откатывается на `games.json`.

### Язык витрины

Посетителю с русским браузером показываются русские названия, всем остальным — английские, если они заполнены, иначе те же русские. Определяется по `navigator.language`, переключателя нет — при желании добавляется в `assets/catalog.js`.

## Этап 2 · Хостинг

Площадка полностью статическая, годится что угодно.

**GitHub Pages** (уже используется для yakistori):

```bash
git init && git add . && git commit -m "playdrop"
git remote add origin https://github.com/ttsshhl/playdrop.git
git push -u origin main
```

Settings → Pages → Deploy from branch → main / root. Домен вешается в Settings → Pages → Custom domain плюс A-записи GitHub у регистратора.

Ограничение — репозиторий до 1 ГБ и файл до 100 МБ. Для тяжёлых WebGL-билдов лучше Railway.

**Railway**: `railway up` в папке, статику раздать через `npx serve`. Так же, как polevoyscreener.

Обязательно HTTPS: без него не будет ни OAuth, ни fullscreen, ни pointer lock.

## Этап 3 · Реклама

`config.js → ads.provider: 'stub'` работает сразу и всегда выдаёт награду — на нём отлаживается механика игры.

Для РСЯ нужен работающий сайт с трафиком и пройденная модерация. После неё: создать блок формата Fullscreen в интерфейсе РСЯ, вписать его ID в `yandexBlockId`, переключить `provider` на `'yandex'` и раскомментировать подключение `context.js` в `game.html`.

Честно про rewarded: полноценный формат «посмотрел ролик — получил награду» в вебе отдают не все сети. Пока сеть не подключена, заглушка показывает таймер и выдаёт награду — игра работает как задумано, просто без выручки.

## Этап 4 · Именованный вход (опционально)

### Зачем он нужен

Анонимная сессия уже даёт: прогресс на сервере, рекорды, серию дней, профиль, работающие RLS. Не даёт трёх вещей:

- **переход между устройствами** — начал на телефоне, продолжил на компьютере;
- **имя в таблице рекордов** — анонимы отображаются как «Гость»;
- **устойчивость к чистке браузера** — очистил данные сайта, и анонимная сессия потеряна навсегда.

Если игры одиночные и таблиц рекордов нет, вход можно не делать вообще. Оставить `provider: null` — кнопки просто не показываются.

### Почему именно Яндекс и почему через Custom Provider

Google OAuth в РФ нестабилен, почтовая отправка с Supabase упирается в SMTP, а Яндекс ID есть почти у каждого. При этом среди встроенных провайдеров Supabase Яндекса нет — там Google, GitHub, Apple, Discord и ещё пара десятков западных. Зато с апреля 2026 есть **Custom OAuth/OIDC Providers**: любой OAuth2-провайдер добавляется вручную, тремя URL. На бесплатном плане таких провайдеров можно завести до трёх.

### 4.1 Приложение в Яндексе

[oauth.yandex.ru](https://oauth.yandex.ru) → создать приложение → платформа «Веб-сервисы». Права: `login:email`, `login:info`, `login:avatar`. Redirect URI пока оставить пустым — он появится на следующем шаге. Сохранить ClientID и Client secret.

### 4.2 Прослойка для профиля

Яндекс отвечает не так, как ждёт Supabase: поля называются `id` и `default_email` вместо `sub` и `email`, а токен передаётся заголовком `OAuth`, а не `Bearer`. Обе проблемы снимает функция из `server/yandex-userinfo/`:

```bash
npx supabase login
npx supabase link --project-ref ВАШ_REF
npx supabase functions deploy yandex-userinfo --no-verify-jwt
```

Флаг `--no-verify-jwt` обязателен: в функцию приходит токен Яндекса, а не Supabase. Получится адрес вида `https://ВАШ_REF.supabase.co/functions/v1/yandex-userinfo`.

### 4.3 Провайдер в Supabase

Authentication → Sign In / Providers → **New Provider** → Manual configuration:

| Поле | Значение |
|---|---|
| Identifier | `custom:yandex` |
| Client ID / Secret | из приложения Яндекса |
| Authorization URL | `https://oauth.yandex.ru/authorize` |
| Token URL | `https://oauth.yandex.ru/token` |
| UserInfo URL | адрес функции из 4.2 |
| Scopes | `login:email login:info login:avatar` |

Форма покажет **Callback URL** — вот его и нужно вписать в Redirect URI приложения на oauth.yandex.ru.

### 4.4 Привязка к анонимному аккаунту

Authentication → General → включить **Manual linking**. Без этого вход создаст нового пользователя, а весь прогресс останется на брошенном анонимном — ровно то, чего мы избегаем.

### 4.5 Включить в конфиге

```js
auth: { anonymous: true, provider: 'custom:yandex', providerLabel: 'Яндекс' }
```

Появятся кнопки входа и подсказка под полкой «Продолжить». Код уже написан так, что при наличии анонимной сессии вызывается `linkIdentity` — прогресс переносится сам.

## Про анонимных пользователей

Каждый заход создаёт строку в `auth.users`, и такие пользователи учитываются в лимитах плана. Стоит завести уборку раз в неделю (Database → Cron):

```sql
delete from auth.users
where is_anonymous = true
  and last_sign_in_at < now() - interval '60 days';
```

Данные удалятся каскадом по внешним ключам. Если на площадке будет заметный трафик, есть смысл включить CAPTCHA (Authentication → Bot Protection) — иначе анонимные регистрации легко накрутить.

## Если что-то не работает

**Пустая страница, в консоли ошибка модулей** — открыто через `file://`. Нужен локальный сервер.

**Игра не грузится в iframe** — путь в `games.json` неверный либо сама игра ставит заголовок `X-Frame-Options`. Свои билды на том же домене такого не делают.

**Лоадер не исчезает** — игра не вызывает `LoadingAPI.ready()`. Либо добавить вызов, либо убрать `#loader` из `game.html`.

**Прогресс не сохраняется на сервер** — не включён анонимный вход (пункт 1.3) или не прописаны ключи. В Network будет 401 от `/auth/v1/signup`.

**Пустая таблица рекордов** — игра не вызывает `setLeaderboardScore`, либо в `schema.sql` не выполнился блок с RPC. Проверить: Database → Functions, там должны быть `submit_score`, `my_library`, `track_play`.

**После входа прогресс обнулился** — не включён Manual linking (4.4).
